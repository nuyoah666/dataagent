# 5 分钟演示脚本（数仓多 Agent 平台）

> 目标：一条主线讲清「同步 → ODS → DWD → 问数 → 运维 → 调度」的多 Agent 协作。
> 全程在浏览器 [http://127.0.0.1:8000/app](http://127.0.0.1:8000/app) 操作。

## 0. 准备（一次性）

```bash
pip install -r requirements.txt
cp .env.example .env          # 填好 LLM_API_KEY 与 MySQL/StarRocks/Mongo/ES 连接
python -m uvicorn src.api:app --host 127.0.0.1 --port 8000
# 问数演示种子数据（在 StarRocks 建跨日期用户快照，幂等可重跑）：
python scripts/seed_semantic_demo.py
```

## 1. 数据集成（确定性 workflow）

在「智能对话」粘贴：

```
把 datax_test.src_user 从 MySQL 增量同步到 StarRocks
```

- 意图路由走**规则**（不调 LLM），配置由**模板 + Pydantic 校验**生成；
- 生成后**挂起到待审批**（写操作人工门禁）；
- 到「全链路监控」打开任务详情：看同步链路图、字段映射、增量条件、DataX JSON。

## 2. 人工审批 + 数据校验

详情页点「通过」→ 执行 DataX → 平台**独立复查**（不信 DataX 自报）：

- 源/目标记录数、主键唯一性、主键非空、抽样逐字段一致；
- 校验明细在详情「数据校验」卡片，可点「重新校验」实时复验。

## 3. ETL（ODS → DWD）

```
把 ods_src_user 加工到 dwd 层
```

- ODS→DWD 走固定模板（纯透传 / 字段映射 / 枚举码值映射）；
- 目标表缺失自动生成 DDL（一键建表）；`INSERT OVERWRITE PARTITION` 幂等。

## 4. 问数（真正的 Agent：语义层 NL2SQL）

```
分析每天的用户数趋势
```

- LLM 只输出**结构化语义查询**（指标/维度/过滤），SQL 由代码**确定性生成**
  （只读 SELECT + 超时 + LIMIT 防御）；
- 结果附带**口径说明卡片**（数据来源/指标公式/维度，与 SQL 同源、LLM 不编造）。

## 5. 运维 Agent（真正的 Agent：RAG + 网络诊断）

造一个失败任务（如目标端不存在/字段不匹配），在失败任务上点「运维诊断」：

- 查运维事故知识库（ES + IK）+ 可选 web 搜索；
- 输出根因 / 影响 / 处置步骤 / 置信度 / 参考链接；
- 确定性可修复项**自动修复并转回待审批**；事故结论**版本化沉淀**回知识库。

## 6. 定时调度（ODS 无人值守）

在成功的对话式集成任务详情点「⏰ 加入调度」，或到「调度」页登记：

- 频率：每日定点 / 间隔分钟（演示用间隔分钟可立刻看到触发）；
- **登记即授权**：到点自动触发并自动通过审批（`operator=scheduler` 写审计）；
- 「立即运行」可手动触发，结果回写最近任务 ID 与状态。

## 讲解主线（面试话术）

1. **确定性优先**：路由/配置/校验/SQL 生成都是规则与模板，LLM 只做意图解析、问数语义、运维诊断这三处开放问题；
2. **状态单一事实源**：tasks.db 为准，LangGraph 只编排，审批/重试/重启都从任务记录重建；
3. **纵深防御**：熔断器、标识符白名单、只读 SQL、密钥加密落库、写操作审批门禁；
4. **可观测 + 可审计**：LangSmith trace + 决策依据时间线 + 审计日志（谁批的、批的配置指纹）；
5. **workflow vs agent**：集成/ETL 是确定性 workflow，运维/问数才是真正"动脑"的 agent。
